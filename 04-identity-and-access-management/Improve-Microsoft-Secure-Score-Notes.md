# Improve Your Microsoft Secure Score

## Overview

Microsoft Secure Score helps organizations:
- Assess their security posture
- Identify risks
- Prioritize improvements
- Create a roadmap toward stronger security

After reviewing Secure Score findings, organizations should:
1. Analyze risks
2. Prioritize recommendations
3. Plan implementation
4. Improve security posture over time

---

# Key Planning Considerations

When improving Secure Score, organizations should consider:

- Potential security risks
- Difficulty of implementation
- Time required
- Impact on productivity
- Secure Score improvement value
- Complexity of deployment

Organizations should rank actions based on:
- Risk reduction
- Business impact
- User impact
- Implementation effort

---

# Security Upgrade Planning

There is no single approach for every organization.

Different organizations have different priorities:

| Organization Type | Possible Approach |
|---|---|
| High-risk industries | Aggressive security implementation |
| Smaller organizations | Focus on easy wins |
| Productivity-focused companies | Low user-impact actions first |

---

# Common Starting Recommendations

Many organizations begin with:
- Low-complexity actions
- High security impact
- Minimal user disruption

Common first steps include:

- Enable MFA for administrators
- Assign multiple Global Administrators
- Enable auditing
- Enable mailbox auditing
- Monitor suspicious sign-ins

---

# Examples of Sign-In Monitoring

Organizations should regularly review:
- Multiple failed sign-in attempts
- Unknown source logins
- Impossible travel scenarios
- Sign-ins from multiple geographies

---

# High-Security Industries

Organizations in:
- Finance
- Healthcare
- Government

Often implement:
- Data Loss Prevention (DLP)
- Information Rights Management (IRM)
- Stronger compliance controls

These solutions:
- Take longer to implement
- Have higher user impact
- Provide stronger protection

---

# Long-Term Security Management

Secure Score should NOT be treated as a one-time project.

Organizations should:
- Continuously monitor security posture
- Reassess risks regularly
- Review score every six months

Security posture changes due to:
- New users
- New administrators
- New services
- Regulatory changes
- Configuration drift

---

# Recommended Action Statuses

## To Address

Meaning:
- Action recognized as necessary
- Planned for future implementation

Also applies to:
- Partially completed actions

---

# Planned

Meaning:
- Concrete implementation plans exist

---

# Risk Accepted

Meaning:
- Organization chooses not to implement recommendation

Reasons may include:
- Business limitations
- Productivity concerns
- Environmental incompatibility

Important:
- No points awarded

---

# Resolved Through Third Party

Meaning:
- Third-party solution already mitigates the risk

Organizations still receive:
- Secure Score points

---

# Resolved Through Alternate Mitigation

Meaning:
- Internal controls already address the recommendation

Organizations still receive:
- Secure Score points

---

# Completed

Meaning:
- Microsoft verified full implementation
- All possible points achieved

Important:
- Status cannot be manually changed

---

# Ranking Logic

Secure Score rankings are based on:

- Remaining points
- User impact
- Implementation difficulty
- Complexity

Highest priority recommendations typically:
- Provide many points
- Have lower implementation difficulty
- Have lower user impact

# Device Category Recommendations

Device recommendations behave differently.

Organizations cannot manually assign statuses.

Instead:
- Secure Score links to:
  Microsoft Defender Vulnerability Management

---

# Exceptions for Device Recommendations

## Global Exception

If a global exception is created:
- Secure Score updates automatically

Update time:
- Up to 2 hours

---

# Device Group Exception

If exceptions apply only to device groups:
- Secure Score does NOT update

Status remains:
- To address
